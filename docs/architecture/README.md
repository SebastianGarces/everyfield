# Architecture contracts

One modular Next.js application shares domain operations between native UI and Evry. [Core](core.md) owns bounded modules/UoW/storage and safe projections. [Auth](auth.md) resolves credential-owned staging and domain acceptance. [Security](security.md) owns exact current scope/cache/file/model boundaries; [audit](audit.md) owns the small platform envelope and explicit exclusions. [Execution](execution.md) names the same-app job and restricted maintenance protocols. [Assessment](assessment.md) owns synchronous material revisions and fixed-run publication. [Reference release](reference-release.md) owns immutable global corpus/derivative promotion and rollback. [Recovery](recovery.md) owns coherent live purge, current witnesses, copy expiry and restore.

[Target schema](../schema/README.md), [closed operations](../catalog/operations.json), [Person consumer registry](person-references.json) and [material writers](material-writers.json) are explicit indexed contracts. [DAG and ownership](../plan/build-plan.md) assign their actual producers. There is no separate backend, global mutable role object, universal workflow/event platform, service per helper or broad private audit browser.

The current design choices are within approved scope. Separate backend candidates were considered: Bun/Hono offers a compact typed HTTP boundary and independent lifecycle; Elysia offers familiar schema-first ergonomics and Bun integration; both add deployment/session/API-contract/operations boundaries without a verified current need. Modular Next.js uses the same typed domain interfaces with less operational overhead. Reconsider an extracted bounded service only after a measured runtime/capacity/ownership requirement; this comparison does not silently activate a new deployment.

Each chosen protocol has a named future proof and failure path. No database, driver, auth, provider or model behavior has been demonstrated by documentation validation.
