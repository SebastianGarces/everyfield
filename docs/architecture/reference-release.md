# Global reference release and derivative activation

Use an immutable global generation manifest and one atomic active pointer. This freezes the engineering release boundary for WIKI-010, COM-008, DOC templates and methodology/retrieval consumers. The approved initial source is the checksummed 96-article/21-section/seven-system-message-template starter in [bootstrap manifest](../reference/bootstrap/manifest.json). [Reference inventory](../reference/manifest.json) preserves the canonical Playbook, original rubric/review, task/ministry/document/mail templates and article inventory. Seven system message templates are not the eleven generated-document templates. Their exact separate inventories/hashes remain explicit.

Initial content acceptance does not rewrite the SME methodology or erase known editorial conflicts. Release validation rejects unresolved contradiction with the authoritative rubric/Playbook and records a content-owner resolution before activating the affected candidate; the starter inventory is accepted, while original source content remains unchanged in its reference package. Customer records, private organization content, reader progress/votes/bookmarks, credentials and unversioned stored vectors are not bootstrap inputs. There is no customer-data migration or legacy migration-chain requirement.

## Manifest and identities

`reference_release` has immutable release_key/generation_id/manifest_hash, schema/manifest version, source artifact revision, rubric/playbook hashes, embedding_model/dimensions, candidate status building/validated/failed, complete_at/validated_at and actual content/operator approval provenance. Validated payload is immutable; only fenced build-state transitions are mutable. Manifest entries include stable logical article ID, exact source ID (`global`), immutable article revision/content hash, slug/section/type/published status/meaningful flag and parent/related/guide mappings. Sections/templates have stable IDs/revisions/hashes, not names as identity. Required six Discovery canonical IDs are explicit.

The manifest also pins approved rubric hash/policy version, Playbook hash, exact document/mail/task/ministry template source hashes and derivation profiles: chunker name/version/settings, deterministic chunk ID(article/source/revision/profile/ordinal/hash), embedding model/dimension/profile/version, expected chunk count/content hashes and complete vector checksums. It states which eligible derivative sets are required for activation. Reproducible content/chunk manifests are byte-identical under repeat build; provider-generated vector bytes are verified/stored by the manifest, with model/profile provenance rather than a claim that inference is always bit-deterministic.

Physical resources are `reference_section`, `reference_template_version`, `reference_chunk` and immutable article versions under candidate generation. `reference_activation` is append-only with monotonic activation_number, release_id, previous_activation_id, reason, actor, activated_at and review provenance. The active-generation pointer is the release named by the maximum committed activation_number; there is no second independently mutable slot or per-release isActive flag. One transaction takes the fixed global activation advisory lock, checks the expected current activation, validates the complete candidate, allocates the next number, and inserts activation/history/audit/receipt plus coherent current global publication mapping. Concurrent activation receives a revision conflict; readers cannot see half a committed activation.

## Build, validation and promotion

1. Create candidate with frozen approved manifest; reject duplicate logical/source revision IDs, invalid topology, unknown related/guide/Discovery identity, slug collisions, malformed dates, unapproved code/executable MDX or tenant/secret fields. Validate global MDX against fixed safe component grammar, with no imports or arbitrary expressions. Curated rich source compiles in controlled validation; organization editor content never executes MDX.
2. Install article/section/template versions parent-first into candidate namespace. Same ID+hash replay is no-op. Same immutable ID with changed hash stops as conflict; it cannot overwrite approved source/plant forks or fabricate successful install.
3. Derive missing chunks/vectors using bounded `reference.derive` jobs with manifest+claim generation fence. Validate all exact required counts/content hashes, model dimensions/provenance, no missing/duplicate/obsolete chunks, valid numerical vectors and complete eligible corpus. A stopped lease/stale manifest cannot mark complete. The prior available snapshot's stored embeddings are not trusted merely because rows exist.
4. Validate source/corpus/rubric/Playbook/template coherence, exact twelve document-format outputs and seven message category mappings as applicable, six Discovery identity mapping, safe rendered topology and protected no-tenant payload. Named semantic checks compare unchanged source rubric/Playbook wording and expected bounded examples. Record passed check IDs/artifact hashes; a “validated” filename is not evidence.
5. Authorized reference operator reviews candidate manifest/diff/check receipt and promotes complete candidate atomically against expected activation_number/ID. Native global publication installs the current article map and eligible derivatives in this same activation transaction, so content/retrieval cannot mix old/new generation. Postcommit cache invalidation/wake-ups are repairable; consumers resolve the latest committed activation plus current entitlement on every request, not trust a stale cache flag.

No provider/model call runs under the activation DB lock. Failed/partial build remains failed or building, with explicit reason/checkpoint; old active generation keeps serving. There is no fallback to half-derived new content, null active pointer, silent copy of old vectors or per-organization adoption gate. Two concurrent promotions have one winner; loser revalidates/reviews against the new active state.

## Consumers and rollback

Assessment/retrieval run pins exact activation/generation and immutable source hashes in its snapshot; its domain publication CAS compares current generation and source/claim revisions. A global generation change cannot let a stale run publish as current. Prior assessment keeps its truthful historical basis under current body rights. Citations name logical article/source/revision/generation; content lookup always checks current entitlement. Wiki default/source-view resolver controls global/organization article choice, hidden default, search/guide/export/context. The methodology rubric/Playbook is its own immutable approved source purpose; organization Wiki edits do not rewrite it.

Organization article publish/edit/hide is live per-article publication under current own-org authority and does not adopt a pinned org edition. It uses sanitized versions and current-entitlement scoped retrieval/search; global derivative eligibility is used only when the resolver selected that global version. An organization-specific source cannot borrow global vectors/body as if it were its own; it can use entitled current full-text/excerpt retrieval while any scoped derivative is built. Derivatives/caches inherit current source rights, and departure denies old body in citations/history/context. No old active generation grants a departed organization body.

Rollback appends a **new activation** pointing to a previously complete validated generation, with reason, operator review and expected current activation_number/ID under the same serialized allocation; it does not erase the failed/new activation or rewind attribution. Revalidate restored generation against current schema/profile eligibility/content approvals and current entitlement/deletion policy. Rollback never restores canceled mail, deleted subjects, personal reading state or overwritten organization customizations. Consumers see the new activation ID even when generation content hash equals an older one; source and activation freshness checks remain truthful.

## Named second-release proof

`REFREL-001` installs initial manifest twice: second is no-op, same-ID changed-hash fails without active mutation. `REFREL-002` second candidate changes one global article meaningfully, another typo-only and one message template; complete activation switches all required mappings/chunks/vectors together, retains organization custom/hide and reader credit, marks only meaningful reader update and emits both customized upstream editor notices. `REFREL-003` a missing/mismatched chunk or embedding timeout leaves old active complete generation serving. `REFREL-004` race two candidates and resume stale worker: only one expected-current activation/valid fenced derivative commit wins. `REFREL-005` rollback makes a new attributable activation of old complete generation while prior publication history stays; no org adoption gate. `REFREL-006` departed organization old citation/cache/export/Evry retrieval denies body across activation and rollback. `REFREL-007` wrong rubric/Playbook/template/source hash and tenant/token canary reject candidate before activation. `REFREL-008` assessment started before activation cannot publish current result afterward; original prior result survives. All are future, not run.

WP-032/033 own source inventory/bootstrap; WP-034/035 own live Wiki/publisher integration; WP-041 owns derivative consumers with assessment/reference owners; WP-004 owns pointer/FK integrity. Actual second-release/browser/model/SQL fault proof closes later. This specification adds no CMS/release platform, paid model usage or provider setup.
