# Domain and API contract specification

This is a future interface specification, not implemented code. The reconciled [capability registry](../evidence/capabilities.json) names each feature's target operations, acceptance gates and owning work packages. Internal parsers, token hashers, SQL helpers and presenters remain source evidence; they are not all public API methods. Better Auth owns credential/session mechanics. Public auth/domain operations are normalized in the registry; `original_v3_operations` retains the audit's original candidate names for review.

## Common envelopes and trust boundary

Commands accept validated domain inputs plus `requestId`, optional actor-scoped `idempotencyKey`, and `expectedRevision` for a mutable subject. Actor and tenant grants come from authenticated server context, never trusted JSON. Return `{data, revision, receiptId, warnings}` on success; warnings must not conceal a partially failed command. Errors contain stable `code`, safe `message`, optional `fieldIssues`, `retryable` and `requestId`. Paginated reads accept bounded page size and opaque cursor and return filtered DTOs plus next cursor/as-of/version. Export/download/assistant reads apply exactly the same object policies.

IDs distinguish Account, Plant, SendingChurch, Network, Person, Meeting, Team, Task, FollowUpObligation, PhaseTransition, AssessmentRun, Artifact and AssistantPlan. LocalDate is `YYYY-MM-DD` with calendar meaning; LocalTime is a wall-clock value; Instant is ISO8601 with offset/UTC; TimeZone is an IANA identifier. Missing evidence is a typed state, not zero/healthy/false. An explicit clear is different from an omitted field; normalize empty form values before command execution. Rich text is a constrained sanitized structure, not executable HTML/MDX from an ordinary user.

Domain operations authorize subject scope and current actor authority before reads/effects; worker and assistant execution recheck grants at effect time. Payload digests guard idempotency replay. An approval refers to an immutable exact plan, not whatever a conversation currently says. Current values/revisions must be visible to a user resolving a stale write.

Framework client generation may consume the schemas but cannot become the only source of truth.

## Accepted product contract amendments · 2026-10-03

[PD-001–005](../decisions/user-rulings.md) are authoritative target amendments; original v2 observations remain evidence. Evry durable operations require exact human review/approval. `checkIns.save/correct/getHistory` remain native planter-only domain operations and are excluded from every Evry tool/model context; ordinary Owner authorization is insufficient for model access. Recording an interview/commitment preserves an already advanced person stage; demotion requires an explicit stage-change command. First-time Vision attendance queries prior attended Vision meetings only, retaining the distinct committed/core-group category and chronological basis.

`followUps.recordOutcome` must distinguish contacted, attempted but no contact, administrative completion, and no longer needed. Only an explicit confirmed-contact outcome may update actual-contact freshness. Task completion and contact freshness are separate measures; no generic `task.completed` subscriber may assume contact. Preserve provenance, idempotent replay and attributable correction history. Exact SQL/transaction/enum shapes remain contract-freeze work; this documentation does not claim a runtime implementation. Other architectural review findings remain unresolved.
