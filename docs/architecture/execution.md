# Durable execution and operating envelope

The selected executor is one authenticated bounded Next route in the same application, using PostgreSQL `job` records and ordinary domain handlers. There is no separately deployed worker, per-feature queue, workflow platform or Vercel Workflow dependency. A best-effort postcommit wake-up may reduce latency; durable due records and a periodic sweep establish recovery. Current mail state is [Communications](../product/communications-notifications.md); reference publication is [Reference release](reference-release.md); backup-only secret isolation is [Recovery](recovery.md).

## Claim and transaction protocol

`job` contains immutable ID/type/typed subject, occurrence key, producer receipt/source revision, dueAt, persisted `job_state` ready/claimed/retry_wait/reconcile/succeeded/failed/cancelled/superseded, attempt count, bounded checkpoint, claim generation/owner, leaseUntil and safe failure code. UI projection aliases map pending→ready, completed→succeeded and blocked_unknown→reconcile; they are not additional persisted states. Reconcile preserves unknown external outcome in the owning mail/effect receipt and never permits blind retry. Superseded work cannot execute against a newer source/approval revision. Unique `(job_type,subject,occurrence_key)` prevents duplicate durable demand. Job payload is IDs/versions, not an unbounded private JSON copy or authority. Domain jobs reload current eligible facts. Private care never becomes a job/metric payload.

The producer transaction writes required domain effect/history/audit/receipt and job/mail intent atomically. Required domain consequences execute in that transaction; outbox does not replace an atomic obligation/task producer. Claim due work in a short transaction using row locks/SKIP LOCKED, increment generation, assign lease, commit before external work. Every checkpoint/completion/publication compare-and-sets ID+generation+claim owner and current subject/required source revision. An expired/reclaimed worker cannot publish or mark complete. Heartbeat extends only its current generation. Cancellation and scope deletion fence the same source/request revision. Application time is not the authority for cancellation deadlines; DB clock is used in the locked transition.

Internal `/api/internal/jobs/tick` accepts only a configured scheduler bearer with constant-time exact comparison, refuses missing/empty secret and rejects arbitrary caller-supplied subjects/job names. Native scoped operator `jobs.manualRun` chooses a registered safe job ID/type and expected state through fresh platform-operator authority/audit, never an Evry free-form command. Dev/preview cron is disabled and fake transports are isolated. One configured minute trigger invokes the route; manual development ticks remain explicit. Actual invocation precision/tier is proven before production and not assumed from vendor selection. [Vercel cron limits](https://vercel.com/docs/cron-jobs/usage-and-pricing) currently give Hobby daily ±59-minute execution and Pro/Enterprise per-minute execution; a free allowance cannot substantiate timely reminders.

Route maxDuration is configured to 300 seconds, internal wall budget 270 seconds with no new work after 240; cancellation/settlement reserve 30 seconds. Claim ≤100 due IDs and execute ≤4 concurrently, at most two current claims per tenant across ticks. Select job types in a fixed rotating round and tenant subjects by oldest eligible last-served cursor; ≤10 IDs from one tenant per claim page. Security/receipt/cancellation work gets a reserved slot, but every eligible type/tenant gets a turn. Digests/reference/deletion cannot be starved by perpetual mail backlog. No fixed first-500 cohort scan discards the tail: persist scan/checkpoint cursors and owed work. Limits are engineering budgets, not customer SLAs. If verified deployment cannot run a required bound, block release or shrink chunks within this design; do not silently add another platform.

The default lease is five minutes, with heartbeat every 30 seconds while running. The registered `assessment.refresh` handler overrides that default with a 120-second job/attempt lease and provider-call timeout of at most 45 seconds, matching the assessment contract. Its shorter lease does not change the 270-second tick budget or another handler's limits. Lease reclaim increments generation and uses the handler recovery rule; no external operation is replayed solely because lease expired. Generic retryable pure/DB work gets 5/10/20-minute backoff, ≤3 attempts, then failed/manual recovery. Provider Retry-After may delay safely; permanent validation/authority/lifecycle refusal cancels/fails without retry. Unknown external outcome enters reconciliation, not generic retry. Operator recovery rechecks current subject/permission, records reason/proof, resumes a safe checkpoint or leaves unknown. Error/time/lag telemetry carries safe job kind/scoped IDs only under operator access.

## Registered work

Lag limits are internal healthy-operation alert thresholds from due/demand commit, not guaranteed delivery. Current permissions/deletion barriers apply at claim, reload, finalization and before external handoff.

| Job / trigger | Checkpoint and timeout | Retry, fairness, lag and manual recovery |
|---|---|---|
| `mail.dispatch`: committed email_intent | frozen recipient/payload/key/provider-ID per ≤100 ordered batch; 10-second API call, 45-second chunk | Confirmed retryable refusal only; lost response→reconcile. Per-recipient checkpoint prevents skipped/duplicate members. Alert due lag >5 minutes; exact provider evidence recovery. |
| `mail.reconcile`: unknown acceptance, scheduled material change or lease loss | intent+original request/actual provider IDs, each observation receipt; 10-second API | Same frozen key within provider retention only; afterward unknown blocks resend. Cancel/sent/unknown remains truthful. Alert unknown unreconciled >30 minutes; provider console/operator evidence. |
| `mail.callback.apply`: durably accepted signed event | unique event ID and applied fact; ≤10 seconds | DB idempotent retry; out-of-order history cannot regress facts. Alert unapplied >5 minutes. Reprocess stored verified event under operator scope. |
| `reminder.sync`: task/meeting revision mutation and periodic repair | entity revision+occurrence, current assignee/guest audience and cancel/regenerate cursor; ≤10 seconds | Rerun current facts, never stale saved body. ≤10 entity chunks/tenant. Alert >5 minutes; resync exact current entity. |
| `digest.compile`: owed local period/coverage cursor | exact recipient/category/zone/date interval and last successful covered boundary; ≤15 seconds | One nonempty dated catch-up, old reminders discarded; authorization rechecked. Cursor advances only with corresponding durable intent. Alert >15 minutes; rebuild same uncovered interval. |
| `assessment.refresh`: material revision/time-only demand | domain-owned immutable run snapshot/asOf/reference generation; 120-second job/attempt lease overrides the default five minutes; each provider/model call ≤45 seconds | Domain publication CAS on source/reference/claim generation; demand identity independent of quiet time-only refresh. Preserve prior result on stale/failure. Alert demand >1 hour; domain-selected retry/manual fresh run, no private care. |
| `reference.derive`: approved candidate manifest | generation+article/version/chunk IDs and hash; ≤64 chunks/call, ≤120-second model call | Rebuild missing deterministic derivatives under candidate fence; never modify active generation. Alert stalled candidate >24 hours; inspect/rebuild/abandon candidate. |
| `document.render`: reviewed generation/import command | template/revision/frozen inputs/output hash and upload identity; renderer ≤30 seconds, importer ≤15 seconds | Safe deterministic retry shares command receipt and immutable key; failed render keeps existing artifact. Alert pending >15 minutes; rerender same inputs or new reviewed correction. |
| `object.reconcile`: upload/finalization failure and periodic sweep | upload ID/object hash/expected owner/ref revision; ≤100 objects/30 seconds | CAS reference check before finalizing/deleting orphan; never remove concurrent ready object. Alert pending >1 hour; inspect exact upload. |
| `feedback.publish`: stored safe feedback publication intent | sanitized fixed payload hash, actual repository identity, opaque occurrence marker, issue receipt; ≤10-second call | Uncertain create searches/reconciles exact destination/marker before retry; ambiguous stays unknown. Alert pending/unknown >1 hour. Operator actual issue evidence, no raw fallback. |
| `deletion.purge` / internal `maintenance.purgeEligibleSubject`: registered deletion job with locked actual account/plant request at/after deadline | subject+request/revision and bounded owned-row/object manifest; ≤100 references/30 seconds | Hidden throughout; CAS each chunk, retry incomplete bytes/rows. livePurgedAt only after coherent eligible live purge. Alert overdue >1 hour; resume manifest after scope verification. |
| `recovery.expiry`: expiry witnesses plus daily sweep | current cutoff/manifest/branch/snapshot/version IDs, non-resetting deletion origin; ≤100 artifacts/30 seconds | Verify provider cleanup asynchronously; failed artifact remains inaccessible and observable. Alert overdue cleanup >24 hours; restricted operator retry/remove exact artifact. |
| `backup.daily`: daily restricted maintenance schedule | consistent DB snapshot+immutable byte inventory/checksums/encryption manifest; restartable chunks, 60-minute run budget | Runs operator-only CLI from same artifact, not ordinary Next secrets. Retry incomplete candidate, promote only fully verified daily copy. Alert latest complete snapshot age >24 hours; operator rerun/restore drill. |

Model/rubric cadence/quality and release ownership stay domain-owned; the executor only supplies durable demand and fences. Evry foreground runs use the same owned operation/receipt/budget semantics and cannot manufacture job permissions. A browser disconnect is observational failure, not cancellation of committed work. Manual rerun cannot reopen deleted subjects, stale approvals or canceled mail.

## Usage and cost envelope

Illustrations checked against official public prices on 2026-10-13; USD before taxes, not actual bills, purchases, forecasts or approved tiers. Actual account settings, regions, credits, eligibility, model selection and any existing contracted discounts are unknown. Use suitable existing free development allowances; before paid production present this itemization with actual measured workload and a concrete approved ceiling. The expected scenario is a planning candidate, not authorization to spend.

Published rate inputs: [Vercel](https://vercel.com/pricing) Pro starts $20/month per developer seat and $20 usage credit; displayed compute starts CPU $0.128/hour, memory $0.0106/GB-hour and invocation $0.60/million. Its [Fluid compute pricing](https://vercel.com/docs/functions/usage-and-pricing) bills all Pro invocations on demand; Hobby's million-invocation allowance does not carry into this Pro illustration. Compute rates shown are examples for listed US regions, not an actual selected region. [Neon](https://neon.com/pricing) Launch lists compute $0.106/CU-hour, database $0.35/GB-month, retained history $0.20/GB-month, snapshots $0.09/GB-month, up to seven-day history and 500 GB project egress then $0.10/GB. Neon Free's limited recovery is insufficient for the selected seven days. These are rate-model inputs, not adopted subscriptions.

[Tigris Standard](https://www.tigrisdata.com/pricing/) lists $0.02/GB-month, Class A $5/million, B $0.50/million, free egress and account allowances first 5 GB/10k A/100k B. Standard avoids the longer minimum retention of archive tiers. [Resend](https://resend.com/pricing) Free lists 3,000 emails/month and 100/day; Pro $20 for 50,000/month with $0.90/1,000 overage. High is modeled as that published Pro+overage arithmetic, not automatic overage approval or a selected Scale plan. Daily burst limits and scheduled/cancel/API behavior require actual verification.

Model pricing example only: [OpenAI Standard short-context gpt-6.1-sol](https://developers.openai.com/api/docs/pricing) lists $2 input/$10 output per million tokens; [text-embedding-3-small](https://developers.openai.com/api/docs/models/text-embedding-3-small) lists $0.02/million input tokens. This chooses neither runtime model nor paid API plan. Quality/latency/data-processing evaluation may require a different approved model and repricing. No cached/batch discount, long-context premium, web/tool/container usage or unverified ZDR benefit is assumed.
