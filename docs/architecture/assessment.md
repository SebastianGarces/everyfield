# Assessment consistency, execution and publication

This contract closes assessment design. Driver compatibility, races, scheduler configuration and model evaluations are future proof gates. It uses the selected single Next.js deployment and PostgreSQL durable job mechanism; no second worker deployment or backend is implied. Product rules are in [methodology-intelligence.md](../product/methodology-intelligence.md). [material-writers.json](material-writers.json) is the closed mutation inventory; adding a material producer requires registering it and its rollback/freshness fixture before producer closure.

## Four identities

| Resource | Identity and authority |
|---|---|
| `assessment_demand` | One typed plant or exact organization subject; `demand_kind`; material/source revision; reference release; policy version; refresh-window or explicit request key. Time-only demand has its own identity even with unchanged data and rubric. Same request key/body converges; changed body conflicts. |
| shared `job` attempt | Demand ID, current monotonically increasing claim generation, lease owner/expiry/heartbeat and bounded attempt state. A lease is execution authority for one attempt, not assessment identity. Reclaim increments generation. |
| `intelligence_assessment_run` / `organization_intelligence_runs` | Immutable run ID; demand ID; job ID and claim generation; one fixed `as_of`; input snapshot/hash/source revision; exact rubric, prompt, corpus and geography versions. Retry can reuse that exact snapshot while eligible; a newer time/input snapshot is a new run. |
| current publication pointer | `plant.current_assessment_run_id` or `organization.current_assessment_id`; changed only by guarded atomic publication. Prior complete results are independently durable. |

Plant runs produce `intelligence_insight` rows; organization runs produce one `organization_intelligence_assessments` row with regional slices inside it. The protected `organization_intelligence_contributor` manifest binds exact plant, organization, current affiliation episode, source/sharing/category revisions and released plant-result version. Organization FKs target the constrained organization parent, never a plant FK or unchecked kind/ID. Typed `intelligence_feedback` targets either a plant insight or an exact-org finding with conditional same-scope integrity.

## Synchronous material revisions

Every relevant native, Evry, bulk/import, correction, merge, removal and system mutation uses the same `DomainTransaction`. It validates current authority/expected revision, writes the fact/current projection, attributable domain history, audit, required intents and increments `plant.material_revision` and affected organization material revisions **in that transaction**. Multiple material changes in one command bump each affected aggregate once. Exact replay/no-op returns the original receipt without a new bump. A failed audit, receipt or revision write rolls the mutation back.

Organization aggregates affected by a plant mutation are resolved through current exact-org relationships/grants and category eligibility; lock affected roots in stable ID order. Do not read raw roster data into an organization projection merely to invalidate it. Sharing/affiliation/category changes bump the affected plant/organization and enforce current permission immediately. Reference activation appends a monotonic reference_activation.activation_number transactionally; publication compares it independently of plant revision. A bounded sweep uses that activation to create affected demands without requiring one giant all-plant mutation.

After-commit wake-up/outbox delivery accelerates work only. A paused/lost wake-up cannot permit old facts to publish because material revision is already durable. The sweep selects never-assessed, changed-source/reference and at-least-seven-day-old complete results directly from durable revisions/time. Private check-ins, their existence/weeks/corrections and private support questions never bump PI/NI revisions or create broad wake-ups.

## Time demand and snapshot boundary

Scheduled selection runs at least daily for time-dependent facts. Each subject's daily UTC refresh window has a stable ID. A seven-day-old unchanged complete result yields a new `time_refresh` demand keyed by that window plus current source/reference/policy, not by the old source/rubric tuple alone. A launch countdown and attestation ages use the new run's fixed instant and stored plant-local calendar, not a clock changing during inference. Material/manual demands are independently idempotent; a newer pending demand can coalesce obsolete unstarted demands but cannot erase attempt/history evidence.

Build all typed facts in one repeatable-read transaction. Capture current source revision, reference activation number and one injected `asOf`, read every required source from that same database snapshot, validate source completeness and persist the immutable run/input before ending the transaction. A snapshot transaction never waits on a model or embedding provider. A driver that cannot provide this consistency contract fails the compatibility gate; it does not switch silently to unrelated parallel queries. The implementation owner proves the selected Neon/driver transaction behavior before closure.

Organization input construction uses the currently released plant version and all exact-org field/category predicates. Aggregate deterministically per rule and geographic group from distinct actual relevant contributors. Keep protected lineage server-only. The model receives only allowed aggregate values, windows, quality flags, structured concern counts and the separate portfolio reference. The server attaches current bounded plant-name/shared-state/shared-reason/canonical-link rows; no raw plant snapshot, directory roster, individual Person, interview/4Cs, private notes, street address or private-care metadata enters NI model input.

## Bounded execution

The authenticated bounded Next executor claims oldest eligible durable work with per-subject single-flight and round-robin tenant fairness; at most ten subjects per invocation and a 270-second soft wall budget within a configured 300-second route limit. Lease expiry is 120 seconds, heartbeat at most every 30 seconds while work is active, and each authoritative write checks current generation. If deployment limits differ, the configuration gate must demonstrate an equivalent bounded schedule/route budget or keep generation disabled with a visible operator blocker. These are engineering limits, not a paid-plan commitment.

Every SDK and provider implicit retry option is explicitly `maxRetries=0`; the registered worker owns and accounts for every actual dispatch. Each provider request has a 45-second maximum and shares the invocation/run deadline. At most four provider attempts per draft and three output drafts are allowed; all attempts share a cumulative run budget of 60,000 input tokens and 12,000 output tokens. Reserve a budget before dispatch, then reconcile actual usage; remaining budget/deadline can stop the ladder before its maximum. Provider retry respects Retry-After/current headers and bounded exponential backoff with jitter. Never sleep through the remaining deadline. Output retries carry the actual accumulated structural/citation/product violations. The final failure diagnostic describes the final draft's failure, not an invented universal cause. Counters preserve `selected = skipped + attempted + deferred_unattempted`; throttled attempted work may consume calls/tokens.

Demand lifecycle is requested→claimable→claimed→settled/deferred/failed/superseded. Run lifecycle is captured→drafting→validated→complete, or deferred/failed/superseded. Lost claims reconcile as abandoned attempt evidence, then a new generation resumes within budget or creates a new run where required. Provider unavailability/budget/deadline defers with a due instant; exhausted invalid outputs fail. Retry deferrals use one shared job with earliest retry plus bounded attempts, not a second assessment queue. Three exhausted scheduled attempts place the demand in operator-review state until new material/reference/time demand or explicit authorized retry. Diagnostics contain IDs/status/codes/usage, never raw model inputs, outputs or private manifests by default.

Plant retrieval failure permits deterministic facts/criteria to remain visible, but no new ungrounded model guidance is published. Report degraded grounding, retain the last valid result with age, and schedule bounded retrieval recovery. NI v1 uses its whole pinned portfolio rubric and aggregate citations; optional reference links must resolve exact authorized passages. Missing mandatory reference or invalid output is `reference_not_ready`/failed, never successful empty/healthy output. No fabricated article citation or fallback plant rubric. Schema-valid output alone does not establish semantic truth.

Source validation is evidence to disposition, not an automatic inherited implementation constraint. Keep phase bounds/reserved reasons, source consistency, exact temporal validity, measured-zero versus Unknown, per-purpose exclusion and bounded budgets as integrity contracts. Replace obsolete global missing-field/legacy profile-time or storage-createdAt proxy guards with the current typed per-field evidence/actual-occurrence contracts; retain the original formula only on its original immutable snapshot. The owner may replace an inherited algorithm/guard if it proves the same current acceptance contract with named cases. Named current proof cases PHASE-CASE-009, PI-METRIC-001, PI-TASK-CONTACT-001, PI-PROVIDER-001 and PI-URGENCY-001 prove these contracts; driver/provider/DB execution remains a future gate.

## Publication fence

In one short transaction, lock subject/current-pointer and job rows in the shared order; compare current source/material revision, reference activation number and rubric/prompt/policy identity, job claim generation and lease validity. For organizations also compare exact current affiliation episode, health/category grants and contributor revisions/eligible set. Current deletion/normal-access suspension prevents publication. Validate every cited fact/value/formula/denominator/window and permitted field before inserting complete insights/assessment, durable summary and completion metadata and advancing the pointer atomically. Store required notification intent in the same transaction; external wake-up follows commit.

If any fence differs, retain safe attempt/run evidence as superseded, publish no current result or notification, leave newer input eligible and create/reuse a fresh demand. An expired/reclaimed worker cannot complete merely because its data revision still matches. Reference rollback is a new activation generation, so a worker from either earlier activation cannot publish into it. A completed run cannot be demoted when an after-commit bus callback fails. Result durability does not depend on that callback.

Plant current/history reads require live actor scope and safe field projection. Organization current/history/export/cache/Evry reads reauthorize the exact contributor and named-row set; if a former contribution is no longer permitted, withhold the invalid pattern or return only a valid recomputed projection. Do not subtract a contributor from prose and claim it was re-evaluated. Shared-findings OFF can leave independently allowed identity/link plus Not shared; ended identity/page reach removes the row. Current request/feedback writers are same-subject Owner/Admin and own currently authorized reader feedback respectively; requests do not grant publication authority. Reads call no model.

## Reference activation and rollback

Exact original inputs and unchanged starter hashes are in [manifest.json](../reference/manifest.json). Global methodology reference_release records release_key/generation_id/manifest/rubric/Playbook hashes, embedding model/dimensions, building/validated/failed state and completion/validation instants. Validated payload is immutable. reference_activation appends monotonic activation_number, release_id, previous_activation_id, reason, actor and activated_at. The active release is the maximum committed activation number selected under one fixed global advisory lock and expected-current CAS; no independently editable active flag or singleton slot.

Global methodology release is immutable content/source/revision manifest plus complete derived corpus/chunker/embedding model/dimensions/checksums and source-to-passage linkage. Source references and the whole rubric are pinned outside embeddings. Ordinary Wiki publication/entitlement follows the knowledge contract; no plant-pinned org edition/adoption gate or historical former-org body entitlement is added.

Validate a candidate generation completely before activation: expected active key set, source/passage hashes, supported language/schema, all article/section/template links, precise target prompt overlay, syntax and semantic fixtures. Partial or failed generation leaves the active pointer intact and records truthful failure. Activate with an expected-generation CAS and audit; activation invalidates new assessment eligibility synchronously. Rollback creates a new activation record pointing to a previously validated immutable generation and retains all attribution. It is never an in-place historical edit. Publish a full generation; removed/trailing stale chunks do not survive. Do not import old vectors without model provenance. The source welcome article has a different hash and never substitutes for the original Playbook.

Current plant prompt assembles the whole exact reviewed rubric-v1 text plus [plant-operational-adapter-v1.json](../reference/plant-operational-adapter-v1.json), with exact assembled hash pinned at activation/run. The preserved historical executable prompt is independently resolvable provenance for original versions, not competing current instructions. The separately versioned operational adapter over original SME v1 applies: apply final C12 biweekly wording, separate Prayer Leader from rhythms, saved explicit training assignments, actual contact/origin evidence and current criterion map. Preserve original prompt bytes and attach a documented diff/semantic fixture suite. A new methodological number/meaning is outside technical drift correction and requires an explicit SME release. EveryField owns separate network rubric releases/feedback; feedback does not automatically activate a new version.
