# Assigned package context

Generate `python3 docs/package-context.py WP-019 --output /tmp/WP-019.json`. The overview contains exact requirement/case selectors, operation IDs, producer/consumer table names, own paths and direct prerequisite outputs. Read the small global orientation/security/audit/workflow contract and its selected product chapter. No v2 checkout, prior ruling chain, historical archive or recursively expanded prerequisite packets is required.

Read the selected detail pages with `--part requirements`, `--part operations`, `--part aliases`, `--part cases` or `--part schema`, plus `--page 1` and subsequent pages through `totalPages`. Each page is bounded to ten full records and196608bytes; no truncation is allowed. Every selected page belongs to the package gate. Schema/contract owners intentionally have a broader indexed task; ordinary adapters consume exact interfaces. Consumer schema definitions and relevant original SME passages are read on demand. Outputs stay outside the repository; there are no86duplicate packet files.

[context-manifest.json](context-manifest.json) is generated from current catalogs. `python3 docs/package-context.py --check-manifest` detects drift; review selections before `--refresh-manifest`. Each selector is a record ID within its named JSON file. Named fixture expected results, current operation field/signature/authority contracts and schema constraints are operative; overview counts are not proof. [DAG](dag.json) owns prerequisites and outputs; [adapter ownership](adapter-ownership.json) owns disjoint files. No assigned packet authorizes implementation or alters canonical progress.

Shared clause IDs are selected transitively and symbolic architecture IDs resolve through [shared-contracts.json](../catalog/shared-contracts.json). Selected acceptance and operation fixtures are included even when their producer-native and later-assistant portions have different owners. Early domain/schema packages prove their applicable native/SQL/contract portion; exact later assistant portions wait for their named adapter dependencies. Only the final whole-target gate closes the complete bundle. No partial producer result is counted as complete native/Evry parity.

A shared clause consumes its exact named producer proof and current interface. Its broad feature applicability does not import other whole-feature bundles into an ordinary consumer packet. Every actually selected owning acceptance bundle retains all of its named cases. Current operation aliases resolve explicitly; unresolved references block the final context gate.

The overview selects each current alias named by its clauses from [current-operation-aliases.json](../catalog/current-operation-aliases.json). Read every selected `--part aliases` page for its exact alias-to-canonical parameter and result mapping; the catalog index declares this source explicitly. Historical source-signature aliases are separate external evidence.

Selected acceptance bundles consume their exact named clauses and operation contracts, even when these are produced elsewhere. The overview marks these consumed references separately from owning clauses and operations. In particular, private-care contracts remain native-only: assistant packages read them to prove denial and original-author native preservation, without receiving model tools or write authority.
