## How to work through this agenda

The rows are **decision units**, not implementation tasks. Each has a recommended answer and a real alternative, with the consequence of choosing between them. A recommended exclusion, later delivery or non-goal requires product disposition just as an inclusion does; nothing is deferred solely because an early slice could omit it. Dependencies name other **decisions**, not only work packages. “None” means the decision can be considered independently, not that implementation needs nothing.

Classes: **Accepted** = current user ruling, closed; **Fact** = source/current-scope fact to reconcile, no vote; **Engineering default** = a defensible implementation choice within approved behavior; **Product** = scope, authority, experience or disclosure choice; **SME** = interpretation of planting methodology; **Empirical** = a choice requiring evidence not established by repository prose. Mixed rows name both. Confidence H/M/L concerns the recommendation/evidence, never approval status. All rows other than Accepted and Fact remain proposals. New numerical choices (approval expiry, reminder time, retention, limits and performance objectives) are explicitly unapproved planning defaults; unlike sourced rubric thresholds, they are not prior user or SME rulings.

Discuss in this order: (1) full-target scope and authority, (2) identity/ownership/privacy, (3) methodology and measurement, (4) clocks and lifecycle, (5) communication/content/Evry detail, (6) operational and empirical choices. The dependency column makes necessary revisits explicit; mutual dependencies identify a group to settle together, not an impossible serialized order. Technical defaults can be recorded in a reviewed ADR without turning each into a user vote. Product/SME behavior must be resolved. For empirical engineering choices, the completed plan may select a design with a named owner, future evidence protocol, pass/fail criteria and fully specified fallback, provided the user knowingly accepts that uncertainty. That is a decided contingency, not completed runtime proof or an unspecified “we will decide later”. The current no-implementation instruction also covers building spikes; proposed evidence work is a plan, not permission to execute it.
