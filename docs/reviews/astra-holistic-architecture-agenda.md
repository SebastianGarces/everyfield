## Recommended architecture as a whole

Recommend **one TypeScript modular monolith, one PostgreSQL system of record, framework-independent domain operations, thin web/assistant adapters, one private-artifact boundary, and one durable worker/effect subsystem**. Domain folders are ownership units, not individual packages, deployables or repositories. No generic workflow engine, command bus, table services or mirrored assistant database is justified by the evidence.

For deployment, my independent proportional default is **modular Next web/API plus a separately runnable durable worker**, under one origin and one repository. This minimizes HTTP/auth/deploy coordination for the currently documented single browser product; the same domain operations remain usable by Evry and workers. This is a recommendation with medium confidence, not a measured verdict against Bun. If an independently operated Bun API is an explicit user preference or an accepted operational requirement, use **Next web plus one Bun API/worker artifact**, with the worker separately runnable when needed; do not create one backend per module.

Within the separate-Bun choice, I would prefer **Elysia when the user's familiarity materially improves ownership**, and Hono when portability or a demonstrably simpler adapter surface is the stronger requirement. No inspected evidence proves Hono superior for this application. Choose topology and framework as separate decisions. Embedded Hono/Elysia in Next is technically supported, but add the adapter only if it removes real routing/client work; otherwise it adds a third set of conventions without removing a deployable. Official examples establish feasibility, not equivalent production behavior: [Elysia with Next](https://elysiajs.com/integrations/nextjs), [Hono with Next](https://hono.dev/docs/getting-started/nextjs), [Better Auth with Elysia](https://better-auth.com/docs/integrations/elysia).

This gives the plan a concrete recommended direction now. Later empirical protocols can disprove assumptions and trigger the named alternative. They are not a substitute for completing decisions, ownership and full-target contracts on paper.
