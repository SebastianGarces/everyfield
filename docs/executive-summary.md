# Current rebuild specification

EveryField is a fresh operational church-planting workspace with native workflows and a first-class reviewed Evry assistant. The original SME Playbook and Plant Intelligence rubric remain authoritative. Current product chapters preserve their meetings, ministries, commitment/interview/4Cs/phase semantics; separately authored Network Intelligence explains scoped organization-shared evidence.

One Next.js/TypeScript/Better Auth/Tailwind/shadcn application on Vercel uses Neon PostgreSQL, private Tigris bytes and Resend. It shares typed server-only domain operations across UI and assistant adapters. Credential changes follow a staged resumable protocol; domain writes atomically commit owned state/history/material revisions/receipt/audit/required intents. Durable work uses bounded same-app PostgreSQL claims; backup keys remain restricted to authorized maintenance.

Plants and typed organizations are separate tenants. One account has one active seat; affiliations grant only their exact approved relationship/projection. Ordinary Owner/Admin administration is shared; workspace deletion is Owner-only. Ministry title adds no access. Native author-private care never enters models, PI, organizations, exports or existence-revealing central logs. Every durable Evry effect requires exact human review and current authorization.

The full target is planned in86small delivery packages with selected per-package contexts, closed operation contracts, target schema, named positive/negative/failure fixtures and a checked prerequisite graph. Slices organize integration and do not remove later capabilities. The context tool avoids loading historical rulings or all catalogs for ordinary package work. [Start here](START-HERE.md), [build plan](plan/build-plan.md), [schema](schema/README.md) and [offline explorer](../everyfield-build-explorer.html) are the main entry points.

Remaining external gates are concrete spending approval, reconciliation of the received merged development workflow, later authorized real provider/repository/credential setup and actual runtime/recovery evidence. No application implementation, customer migration, provider spend, database change, PR or deployment is authorized by this document plan.
