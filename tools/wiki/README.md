# Wiki tooling

Published source lives in `docs/reference/wiki/seed.json` with its manifest, backlog and drafts.
The original `docs/reference/bootstrap/` bytes remain unchanged. `check-seed` verifies both the
living source and its `derivedFrom` bootstrap payload hash.

Node 24+ runs native TypeScript through `bin/wiki`. Install the exact tooling dependencies
with `cd tools/wiki && pnpm install --ignore-workspace`; this directory has its own lockfile
and is outside the application workspace. Python 3 handles seed JSON bytes and hashes.
Playwright 1.56.1 uses Chromium build 1194. Run `bin/wiki help` for commands.

Lint compiles MDX with GFM and checks the syntax tree before rendering. It permits only static
Callout components and Markdown. Imported seed quotes may omit a translation tag and retain
the existing KJV/NLT tags and verse-part references. New drafts require `(LSB)`. Lint validates
format, not factual accuracy or scripture wording; Opus and the human approver own those checks.
The renderer reuses the handoff tokens and prototype prose/callout CSS with system font fallbacks.
It is a review preview, not application acceptance evidence. HTML and PNG output must live outside
the repository. For example:

```sh
bin/wiki lint --seed
bin/wiki check-seed
bin/wiki roundtrip
bin/wiki shot administrative/legal/setting-up-501c3 --out /tmp/wiki-review
bin/wiki shot administrative/financial/counting-procedures --out /tmp/wiki-review --mobile
bin/wiki pr-images 5 /tmp/wiki-review/example.png --update-body
```

Promotion requires chat or PR-comment approval and `--reviewed-sha`, the full reviewed PR head.
It compares the entire tracked draft file against that commit, then records `--approved-by` and
`--pr` in the manifest. The CLI does not authenticate a human's chat approval. The coordinator
must verify it, and Sebastian merges after Opus review. See the [skill](../../.agents/skills/wiki-article/SKILL.md).

`pr-images` uses a per-command 50 MiB Git HTTP buffer for the full-page PNG upload pack.
The gist id is saved in the PR before upload so a failed push can reuse it.

`--seed-dir <dir>` on lint/render/shot/promote/check-seed/roundtrip supports disposable seed
copies for proof. It does not redirect the source Playbook. Tests create a separate temporary
Git repository for the reviewed draft. Run `bin/wiki`'s Node 24 binary with `--test` on
`tools/wiki/tests/*.test.ts`, or `pnpm test` here with Node 24 on PATH.

Promotion stages both JSON files before replacing them and retains the draft until validation
succeeds. A `.wiki-promote.lock` directory prevents simultaneous seed writers. After a process
crash, inspect the seed/manifest diff and draft first. Restore both seed files from Git if the
pair is incomplete, remove only the stale lock and `.wiki-tmp` files, and retry from the reviewed
draft. Do not remove a live writer's lock. This is a local file update, not database activation.

`check-seed` verifies article, section, original-order template, Playbook and payload hashes and
identity/path constraints. `expectedChunks` and `validation` in the manifest are historical import
and embedding evidence, not regenerated by editorial promotion. `verification.json` is immutable
original-import evidence. New article versions are recorded separately in manifest `releases`.
